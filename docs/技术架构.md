# Explorer2Dialog Windows 11 MVP 技术架构

程序是独立的 x64 Windows 可执行文件，以 C# 5 和 .NET Framework 4.8.1 构建。主线程托管 WinForms 消息循环、托盘菜单及窗口事件。资源管理器读取在独立 STA 线程执行，跨进程 UI Automation 查询在 MTA 工作线程执行。[UI Automation 线程模型](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)

~~~mermaid
flowchart LR
    E[前台 Explorer] --> W[SetWinEventHook]
    D[文件对话框显示或获得前台] --> W
    W --> T[ExplorerTracker · Shell COM]
    T --> C[FolderCache · 最后有效目录]
    W --> L[DialogLifecycle · 窗口可见周期]
    L --> Q[DialogDetector · 权限与控件]
    C --> N[DialogNavigator · 焦点核验和目录输入]
    Q --> N
    N --> F[确认已提交目录、文件列表与文件名]
~~~

## 资源管理器与目录缓存

`ExplorerTracker` 延续 PoC 的 Shell COM 路线。用 `IShellWindows` 枚举 `IWebBrowser2` 对象，根据顶层窗口 HWND 及 `IShellBrowser.GetWindow` 返回的活动 `ShellTabWindowClass` 子窗口匹配标签页。对匹配的对象读取 `LocationURL`，将 `file:` URL 转成规范文件路径。匹配前后检查活动标签。前台事件触发立即采样，当 Explorer 持续在前台时，每次读取后等待约 200 ms，覆盖不产生前台事件的标签和目录切换。

离开 Explorer 时对最后活动的 Explorer 窗口采样一次，此后工作线程等候事件。切换活动标签或离开 Explorer 时显式释放活动 COM 引用，枚举临时对象在循环内释放，Shell COM 异常时重置引用。停止时由 STA 负责释放剩余 COM 对象。

`FolderCache` 保持最近有效路径。前台转换生成新的采样代次，较老结果无法覆盖较新采样。已确认的虚拟 Shell 目录让缓存保留上次有效路径。活动标签结果未能确认时，对话框最多等 350 ms，仍无法确认则跳过该次导航。导航前另外检查目录属性并尝试列举，防止对已经移动、删除或无法访问的路径发起输入。

## 文件窗口识别与生命周期

`WindowEventMonitor` 监听前台切换和窗口级隐藏、销毁。`EVENT_SYSTEM_FOREGROUND` 驱动候选窗口验证，也提供每次导航计时的零点。回调在注册线程的 WinForms 消息循环执行，屏蔽自身进程的窗口事件。[WinEvent 事件常量](https://learn.microsoft.com/en-us/windows/win32/winauto/event-constants) · [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)

`DialogLifecycle` 在候选对话框获得前台时建立实例，绑定 HWND、进程、线程和生命周期标识。每次切回记录新的 `visit`。同一窗口只在本次缓存目标与上一次已处理目标不同时再次尝试导航。隐藏或销毁后释放状态，旧时间戳的关闭事件无法结束较新的周期。

`DialogDetector` 对已获得前台句柄的对话框限时等待实际显示，然后确认窗口和进程完整性。使用 Win32 控件 ID 和现代文件窗口的 UIA 结构做判定，包含 Shell 容器、文件列表、导航树、文件名控件及面包屑。窗口标题仅用于给日志分类，分类结果支持用 `kind=file` 记录其他语言的标准布局。传统 Win32 结构可识别为 `legacy-recognized`。实际跳转走已验证的现代文件窗口分支。

每个时刻最多一个仍可操作窗口的工作项，并限制最多两个未结束工作项。一个已撤销但在等待同步 UIA 返回的工作项允许下一个候选窗口继续处理。窗口已失焦、关闭或功能暂停时撤销操作。工作项开始后 4.5 秒到期，后续检查会阻止继续输入。提供程序迟迟未返回同步调用时，工作线程可能继续等待，主消息循环仍可响应。[已知限制](已知限制.md)

## 已打开对话框的后台同步

当 Explorer 在前台时，程序仅检查缓存和最近活动的候选对话框。进程启动前已打开的窗口，在候选唯一时可以接管。读到新本地盘符目录后，工作线程核验窗口、进程、界面结构、路径和当前 Explorer 目录，再通过文件窗口自带的目录树定位目标。盘符尚未出现在树中时，先按 Windows 提供的本地显示名找到并展开「此电脑」。[Windows 已知文件夹](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid) · [TVM_EXPAND](https://learn.microsoft.com/en-us/windows/win32/controls/tvm-expand)

后台导航只向经过验证的目录树控件发送窗口消息。选择后复核目标地址、文件列表及原文件名。Explorer 保持前台，路径已被更新时，切回同一个对话框会复用已处理状态。目录树无法定位时保留前台导航路径。后台日志用 `follow` 标记从调度起的时间，和前台事件计时对应不同的触发点。[TVM_MAPHTREEITEMTOACCID](https://learn.microsoft.com/en-us/windows/win32/controls/tvm-maphtreeitemtoaccid) · [TVM_SELECTITEM](https://learn.microsoft.com/en-us/windows/win32/controls/tvm-selectitem)

## 导航与终止

`DialogNavigator` 沿用 PoC 的混合控制方案。锁定当前窗口及键盘焦点，检查最近用户输入，再发送 `Alt+D`。仅在焦点实际位于目标对话框地址栏的 `Edit/41477` 时，尝试用 UIA `ValuePattern` 写入路径。必要时回退到 Unicode `SendInput`。提交前再次检查前台、窗口生命周期与地址编辑框焦点。Enter 用于地址栏提交，随后复查已生效的面包屑、可见文件列表及原始文件名。目录已相同时只做确认。

进程清单声明 `asInvoker`。通过目标令牌完整性级别做同级检查，级别未知或不同直接跳过。完成导航后焦点可能留在折叠的面包屑工具栏，下一次允许在此发出 `Alt+D`。用户已进入地址编辑框时保留该编辑状态。[完整性控制](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control) · [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

`DialogInputMonitor` 在待处理的文件窗口前台观察按键、窗口内容区点击和滚轮。Explorer 与有可见文件窗口的应用主窗口获得前台时，观察鼠标对文件窗口的激活点击。回调在 Explorer2Dialog 的消息线程运行，保留短期窗口标识、时间及是否发生用户操作的标记。鼠标移动、标题栏点击和快捷键释放可正常完成切换。监听随窗口切换、暂停或退出收回，程序发出的键盘输入带有本进程的标记。日志仅包含操作状态，不记录键值或鼠标位置。[键盘低级回调](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) · [鼠标低级回调](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)

日志中的 `foreground_qpc` 由 WinEvent 前台事件时间换算到 Stopwatch。`shown_ms` 记录是否在切回时已显示，`directory_ms` 是首次成功读取已提交的目录，`confirm_ms` 包含文件列表与原文件名复核。[实测口径](测试报告.md)

`TrayApplication` 提供暂停、查看缓存与退出。退出路径销毁托盘图标、移除 WinEvent 注册、撤销活动窗口工作项并通知 Explorer 线程结束。会话内互斥量限制为一个实例。

## 与 PoC 的整合

复用了活动标签页 COM 匹配、文件 URL 转换、WinEvent 监听、标准窗口结构、地址栏焦点核验和显示真实目标目录后的确认逻辑。MVP 增加常驻托盘、采样代次、窗口可见周期、完整性过滤、并发限额及分阶段计时。通过预缓存、限制 UIA 查询范围、合并顶层控件查询和复用查询结果，缩短识别和导航阶段的等待。[本版实测](测试报告.md)
